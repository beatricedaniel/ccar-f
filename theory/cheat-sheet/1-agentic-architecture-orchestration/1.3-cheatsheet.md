# Domain 1 · Task 1.3 — Configure Subagent Invocation, Context Passing, and Spawning

**Exam objective:** Spawn subagents (via the Task/Agent tool), scope their tools with least privilege, and pass all needed context explicitly since subagents are isolated.

## Key concepts
- **Task tool** (Claude Agent SDK) is the primary mechanism to spawn subagents: orchestrator calls `Task` with a **description** of work, an optional set of **allowed tools**, and **any context** the subagent needs. SDK launches a fresh agent loop, runs it to completion, returns the result to the orchestrator.
- **Tool scoping via `allowedTools` = least privilege.** Each subagent gets only the tools it needs (a file-reading subagent should NOT have write/shell tools). **If `allowedTools` is omitted, the subagent inherits ALL tools in the environment** — a common source of unintended side effects.
- **Context isolation:** subagents do NOT share memory or conversation state with the orchestrator or each other. Everything a subagent needs (user intent, prior results, file contents, config) must be passed explicitly in its task prompt / initial `messages` array.
- Relying on shared global state or assuming a subagent "remembers" from the parent = design error producing silent, hard-to-debug failures.
- **Parallel execution:** independent subagents run safely and efficiently with `Promise.all` (each is isolated). Use `Promise.allSettled` when partial failures are acceptable.
- In Claude Code, a subagent runs in **its own context window** with a custom system prompt, specific tool access, and independent permissions. It receives only its system prompt + basic environment (working dir), NOT the full Claude Code system prompt or parent conversation.

## Patterns & when to use them
- **Spawn a subagent when** a side task would flood the main conversation with search results/logs/file contents you won't reference again — the subagent does that work in its own context and returns only a summary.
- **Define a custom subagent when** you keep spawning the same kind of worker with the same instructions.
- **Parallel (`Promise.all`)** when subagents are truly independent; **sequential (`await` loop)** only when one depends on another's result.
- **Same data to multiple subagents:** pass the data explicitly to each — never share via reference.
- **Model per subagent:** cheaper model (e.g. `claude-haiku-4-5`) for simple chunk summarization; stronger for complex review.

## Gotchas / exam traps
- **Common Mistake 1 — Omitting `allowedTools`:** subagent inherits all tools; a summarizer with accidental shell access = side effects. Always declare the minimal tool set.
- **Common Mistake 2 — Passing context by reference / shared state:** subagents can't read the orchestrator's history or globals; every needed fact must be in the subagent's initial `messages`.
- **Common Mistake 3 — Running independent subagents sequentially:** `await` in a loop wastes wall-clock time ∝ number of agents. Use `Promise.all`/`Promise.allSettled`.
- Claude Code specific: an **Agent tool call that omits `subagent_type` fails** ("subagent_type is required") when there's no `general-purpose` subagent to fall back on.
- To **prevent any delegation**, deny the `Agent` tool itself in `permissions.deny`. To block one built-in type, add it to `permissions.deny`.
- A subagent whose `tools` list names a tool that resolves to nothing usually **fails to launch** with an error naming the entries.
- **Built-in Explore/Plan skip CLAUDE.md and git status** (fast/cheap); every other subagent loads both.

## Quick reference

### Subagent frontmatter fields (Claude Code `.md` / `--agents` JSON)
| Field | Required | Notes |
|---|---|---|
| `name` | Yes | Unique, lowercase+hyphens; hooks see it as `agent_type`; no `:` (reserved for plugin ids) |
| `description` | Yes | When Claude should delegate to this subagent |
| `tools` | No | Tools it may use; inherits all if omitted |
| `disallowedTools` | No | Tools to deny, removed from inherited/specified list |
| `model` | No | `sonnet`/`opus`/`haiku`/`fable`, full ID, or `inherit` (default) |
| `permissionMode` | No | `default`/`acceptEdits`/`auto`/`dontAsk`/`bypassPermissions`/`plan`/`manual` |
| `maxTurns` | No | Max agentic turns; on limit, output marked **partial** and Claude can resume |
| `mcpServers` | No | MCP servers available to subagent |
| `hooks` | No | Lifecycle hooks scoped to subagent |
| `memory` | No | Persistent scope: `user`/`project`/`local` — enables cross-session learning |
| `background` | No | `true` keeps subagent in background |
| `effort` | No | `low`/`medium`/`high`/`xhigh`/`max`; overrides session effort |
| `isolation` | No | `worktree` = isolated git worktree copy (auto-cleaned if no changes) |
| `color`, `initialPrompt` | No | Display color; auto-submitted first user turn |

Note: plugin subagents ignore `hooks`, `mcpServers`, `permissionMode` (security).

### Subagent scopes (precedence, highest→lowest)
1. Managed settings (org-wide) → 2. `--agents` CLI flag (session) → 3. `.claude/agents/` (project) → 4. `~/.claude/agents/` (user) → 5. plugin `agents/` dir.

### Built-in subagents
- **Explore:** fast, read-only codebase search; Write/Edit denied. Thoroughness levels: `quick` / `medium` / `very thorough`.
- **Plan, General-purpose, Other.**
- Disable built-ins: `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1` (Explore/Plan); SDK: `CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1`.

### Orchestration code shape
- `Promise.all([client.messages.create({...subagent1}), client.messages.create({...subagent2})])` — each isolated call has its own system prompt, tools, and full context in `messages`.
