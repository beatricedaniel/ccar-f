# Domain 2 · Task 2.4 — Integrate MCP Servers into Claude Code and Agent Workflows

**Exam objective**: Register, configure, and manage MCP servers in Claude Code via `.mcp.json`/CLI — choosing transports and config scopes, exposing resources vs. tools, and addressing them with RFC 6570 URI templates.

---

## Key concepts

- **MCP (Model Context Protocol)** — open standard for AI-tool integration. Servers give Claude Code access to external tools, databases, and APIs. Separates *providing context* from *the LLM interaction*.
- **`.mcp.json`** — primary config file that registers MCP servers (which servers, how to launch, what env). Claude Code reads it at startup and connects before/around the session. Lives at the **project root** and is checked into version control (project scope).
- **Three ways to declare a server**: (1) `claude mcp add` CLI, (2) JSON in `.mcp.json` / `~/.claude.json` / `claude mcp add-json`, (3) an `mcpServers` block copied from another client.
- **Two primitives an MCP server exposes**:
  - **Tools** — *side-effecting actions* (create, delete, mutate). Appear in the tool-call history; consume output tokens.
  - **Resources** — *read-only, addressable context* injected as attachments. Identified by a URI. Use for large/read-only content (docs, DB records, file contents).
  - Servers can also expose **prompts** (become `/mcp__server__prompt` slash commands) and support **elicitation** (server requests structured input mid-task via a dialog).
- **Transports** (how Claude Code talks to a server): **stdio** (local child process), **HTTP / Streamable HTTP** (remote, recommended), **SSE** (remote, *deprecated* — use HTTP), **WebSocket/ws** (remote, bidirectional push).
- **Config scopes**: **local** (default, this project, private), **project** (`.mcp.json`, shared via VCS), **user** (all your projects, private). Plus **plugin-provided** servers and **claude.ai connectors**.
- **`env://` / `${VAR}` expansion** — never hard-code secrets; pull from the environment at connection time.

## Patterns & when to use them

### Transport types
| Transport | Use when | Config `type` | CLI flag |
|---|---|---|---|
| **stdio** | Local tools, direct system access, custom scripts. Server lifetime bound to the session; no networking. | `"stdio"` | `--transport stdio` (put launch command after `--`) |
| **HTTP** | Remote/cloud services. **Most widely supported**; recommended. Supports OAuth + `--transport`. | `"http"` (alias `"streamable-http"`) | `--transport http` |
| **SSE** | Legacy remote endpoints that only expose SSE. **Deprecated** — prefer HTTP. Must be reachable at startup. | `"sse"` | `--transport sse` |
| **WebSocket** | Remote server that pushes events unprompted (bidirectional). No OAuth, no `--transport` support. | `"ws"` | *(JSON only — `add-json`)* |

- HTTP/SSE/`claude.ai connector` servers have a **per-request timer** (60s default to first byte).
- **stdio** servers get `CLAUDE_PROJECT_DIR` set to the project root in their environment.

### Resources vs. tools (decision rule)
- **Action with a side effect** → **tool** (`server.tool(...)` / `registerTool`).
- **Large read-only context to inject** → **resource** (`server.resource(...)`), so you don't bloat tool-call history or burn output tokens.
- Resources are read-only → matters for permission models and audit trails.
- **Reference a resource in a prompt** with `@server:protocol://resource/path` (e.g. `@github:issue://123`, `@docs:file://api/authentication`). Type `@` to autocomplete.

### Adding MCP servers to Claude Code
```bash
# HTTP (remote, recommended)
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# SSE (legacy)
claude mcp add --transport sse asana https://mcp.asana.com/sse

# stdio (local) — launch command goes AFTER `--`
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server

# WebSocket — JSON only
claude mcp add-json events-server '{"type":"ws","url":"wss://mcp.example.com/socket","headers":{...}}'
```
- Choose scope with `--scope local | project | user` (default: **local**).
- `claude mcp add` **saves config without validating credentials** — a bad token is accepted, then the server fails to connect. Verify with `/mcp`.

## Gotchas / exam traps

- **Never commit secrets** to `.mcp.json` — always use `env://VAR` / `${VAR}`. A literal key is exposed to every contributor + CI.
- **`type` field is required** in JSON. An entry with a `url` but **no `type` is read as a stdio server and fails**. There is *no default transport* — omitting `type` gets the entry rejected/skipped.
- **Missing env var**: `env://` — Claude Code **surfaces an error** rather than passing an empty string. `${VAR}` with no `:-default` → loads the server but leaves `${VAR}` **literal/unexpanded** and warns.
- **SSE must be running at startup** (unlike stdio, which Claude Code spawns). An offline SSE endpoint can silently drop all its tools unless you check logs.
- **Scope confusion**: putting a project-specific server in **user scope** makes it run in unrelated sessions (waste + exposure). Project-specific → project scope.
- **Precedence**: when the same server name is defined in multiple scopes, **project scope wins over user**. Full precedence chain: **local → project → user → plugin-provided → claude.ai connectors**. (Note: a server you add locally beats a claude.ai connector at the same URL.)
- **Conflating tools & resources**: returning big read-only docs via a *tool* bloats history and wastes output tokens — expose as a *resource*.
- **Server-name charset**: `claude mcp add` names allow only letters, numbers, hyphens, underscores.
- **Project-server approval / workspace trust**: project `.mcp.json` servers stay **"Pending approval"** until you trust the workspace (run `claude` interactively and accept the trust dialog). A cloned repo can't approve its own servers.
- **MCP output limits**: warning at **10,000 tokens**; default max **25,000 tokens** (`MAX_MCP_OUTPUT_TOKENS`). Server authors can raise via `_meta["anthropic/maxResultSizeChars"]` (ceiling 500,000 chars).
- **Root-level schema combinators** (`anyOf`/`oneOf`/`allOf` at schema root) aren't accepted by the API — Claude Code flattens them; nested-in-`properties` combinators pass through.
- **`claude mcp serve`** — runs Claude Code *itself* as a stdio MCP server for other clients.

## Quick reference

### `claude mcp` CLI
| Command | Purpose |
|---|---|
| `claude mcp add [opts] <name> -- <cmd> [args]` | Add a server (stdio launch cmd after `--`) |
| `claude mcp add --transport http\|sse <name> <url>` | Add a remote server |
| `claude mcp add-json <name> '<json>'` | Add from a JSON object (the value inside `mcpServers`) |
| `claude mcp list` | List servers + health (`✔ Connected`, `! Needs authentication`, `✘ Failed to connect`) |
| `claude mcp get <name>` | Show one server's details |
| `claude mcp remove <name> [--scope <s>]` | Remove a server |
| `claude mcp login <name>` / `logout <name>` | Run/clear a server's OAuth flow from the shell |
| `claude mcp serve` | Run Claude Code as an MCP server |
| `/mcp` (in-session) | Panel: status, authenticate (OAuth), reconnect, toggle on/off |
| Flags | `--scope`, `--transport`/`-t`, `--header`/`-H`, `--env`/`-e KEY=value`, `--callback-port`, `--client-id`, `--client-secret` |

### Config scopes
| Scope | Loads in | Shared | Stored in |
|---|---|---|---|
| **local** (default) | Current project only | No | `~/.claude.json` (keyed by project path) |
| **project** | Current project only | Yes (VCS) | `.mcp.json` in project root |
| **user** | All your projects | No | `~/.claude.json` |

> "local scope" for MCP ≠ general local settings (`.claude/settings.local.json`). MCP local servers live in `~/.claude.json`.
> The objective PDF also cites user scope as `~/.claude/mcp.json` or `~/.claude/settings.json` under `mcpServers`.

### `.mcp.json` shape
```jsonc
{
  "mcpServers": {
    "local-db": {
      "type": "stdio",
      "command": "node",
      "args": ["./tools/db-server/index.js"],
      "env": { "DATABASE_URL": "env://DATABASE_URL" }
    },
    "shared-search": {
      "type": "sse",                 // or "http" / "ws"
      "url": "https://search.internal.example.com/mcp/sse",
      "env": { "SEARCH_TOKEN": "env://SEARCH_TOKEN" }
    }
  }
}
```
- **Env expansion** works in `command`, `args`, `env`, `url`, `headers`. Syntax: `${VAR}` and `${VAR:-default}`.
- Extra fields: `timeout` (ms, per-server tool timeout), `alwaysLoad: true` (exempt from tool-search deferral), `headersHelper` (script that emits auth headers), `oauth` (`authServerMetadataUrl`, `scopes`).

### MCP resource URI schemes (from the spec — not exhaustive; custom schemes allowed)
| Scheme | Meaning |
|---|---|
| `https://` | Web resource the client can fetch itself |
| `file://` | Filesystem-like (need not map to real files; `inode/directory` for dirs) |
| `git://` | Git version control |
| custom, e.g. `db://`, `customers://` | Server-specific addressing |

**Resource fields**: `uri` (required), `name` (required), `title`, `description`, `mimeType`, `size` (all optional). **Contents**: `text` or `blob` (base64). **Annotations**: `audience` (`["user","assistant"]`), `priority` (0.0–1.0), `lastModified` (ISO 8601).
**Protocol methods**: `resources/list`, `resources/read`, `resources/templates/list`, `resources/subscribe`, notifications `notifications/resources/updated` & `.../list_changed`. **Capabilities**: `resources: { subscribe, listChanged }`. **Errors**: `-32002` resource not found, `-32603` internal.

### URI templates — RFC 6570 (`{var}`, `{+var}`, `{#var}`, …)
A **resource template** parameterizes access: `customers://{id}/profile` → resolves to `customers://42/profile`. Declared via `uriTemplate` in `resources/templates/list`; in the TS SDK: `new ResourceTemplate("customers://{id}/profile", { list: undefined })`.

**Operators** (first char inside the braces; expansion given `var="value"`, `hello="Hello World!"`, `path="/foo/bar"`, `x="1024"`, `list=("red","green","blue")`):
| Op | Name | Level | `{op var}` example → expansion |
|---|---|---|---|
| *(none)* | Simple string | 1 | `{var}` → `value`; `{hello}` → `Hello%20World%21` (pct-encodes reserved) |
| `+` | Reserved | 2 | `{+var}` → `value`; `{+path}/here` → `/foo/bar/here` (keeps reserved chars) |
| `#` | Fragment | 2 | `X{#var}` → `X#value`; `{#hello}` → `#Hello%20World!` |
| `.` | Label (dot-prefixed) | 3 | `X{.var}` → `X.value` |
| `/` | Path segments | 3 | `{/var}` → `/value`; `{/var,x}/here` → `/value/1024/here` |
| `;` | Path-style params | 3 | `{;x,y}` → `;x=1024;y=768` |
| `?` | Form-style query | 3 | `{?x,y}` → `?x=1024&y=768` |
| `&` | Query continuation | 3 | `?fixed=yes{&x}` → `?fixed=yes&x=1024` |

**Value modifiers** (Level 4, suffix on the variable name):
- **`:N`** prefix — first N chars: `{var:3}` → `val`.
- **`*`** explode — expand each member of a list/assoc-array separately: `{/list*}` etc. (`{list}` → `red,green,blue`; `{keys}` → `semi,%3B,dot,.,comma,%2C`).

**Levels**: 1 = simple `{var}` only · 2 = adds `+` and `#` · 3 = multiple vars + `.` `/` `;` `?` `&` · 4 = adds `:N` and `*` modifiers. Multiple vars per expression are comma-separated: `{?q,lang}`. Undefined vars are omitted from the expansion.

### `mcp://` resources — reference form in Claude Code
- In a prompt: `@server:protocol://resource/path` (e.g. `@github:issue://123`).
- Plugin-bundled tool name: `mcp__plugin_<plugin-name>_<server-key>__<tool-name>`; plugin server scoped name: `plugin:<plugin-name>:<server-name>`.
- MCP prompt as command: `/mcp__<servername>__<promptname> [args]`.
