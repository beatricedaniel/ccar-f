# Domain 3 · Task 3.6 — Integrate Claude Code into CI/CD Pipelines

**Exam objective**: Run Claude Code non-interactively (headless `-p` mode) inside automated pipelines and GitHub Actions — using machine-readable output, JSON-schema-constrained responses, scoped tool permissions, and CI secrets — while respecting stateless session isolation.

---

## Key concepts

- **Headless / non-interactive mode = `-p` (`--print`)**: passes a prompt on the command line, runs once, exits. No REPL, no user input. Composable with shell scripting and pipeline tooling.
- **Four capabilities that make CI/CD integration work**: `-p` (non-interactive execution) · `--output-format json` (machine-readable output) · `--json-schema` (enforce response shape) · **stateless session isolation** (no context leakage between runs).
- **Exit codes**: `0` on success, **non-zero on failure** (API errors, rate limits, schema validation failures, missing auth). Scripts branch on exit status; use `set -e` to catch failures. Invalid flag → error to stderr *before* the run starts. Failure *inside* the run (e.g. missing auth) → printed as the result on stdout. SIGTERM → exit code **143** (leaves the turn unfinished, runs `SessionEnd` hooks).
- **Session isolation**: every `claude -p` invocation is completely stateless — no persistent session, no memory of prior runs, no shared context between jobs. This is the *correct default* for pipelines (reproducible, prevents one PR contaminating another). For multi-turn, chain explicitly (pass prior output as input, or use `--continue` / `--resume <session_id>`).
- **stdin piping**: non-interactive mode reads stdin, so you can pipe context in (`git diff | claude -p "..."`). **Piped stdin capped at 10MB** → exceed it and Claude exits non-zero with a clear error; write large inputs to a file and reference the path instead.
- **GitHub Actions**: the `anthropics/claude-code-action@v1` runs Claude Code inside a repo's workflows. Mention **`@claude`** in a PR/issue comment (interactive mode) OR give it a `prompt` input (automation mode). Built on the Agent SDK.
- **JSON Schema**: a vocabulary for constraining JSON shape (types, required fields, enums) — enables safe deserialization into typed structures.

## Patterns & when to use them

### Headless mode for CI/CD (`-p`)
```bash
claude -p "Review this diff for security issues and list findings"
git diff HEAD~1 | claude -p "Summarize this diff as a PR description. Be concise."
```
Use for: automated code review, PR-description generation, test generation, project-specific linters (`npm run lint:claude` wrapping a `-p` call). Exits non-zero on failure so pipeline steps can gate on it.

### Bare mode for CI (`--bare`)
- Add `--bare` to **reduce startup time** by skipping auto-discovery of hooks, skills, custom commands, subagents, plugins, MCP servers, auto memory, and `CLAUDE.md`.
- Ensures the **same result on every machine** — a teammate's `~/.claude` hook or a project `.mcp.json` server won't run.
- Without `--bare`, a `-p` session loads the *same context an interactive session would*, runs hooks in `.claude/settings.json`, and connects `.mcp.json` servers **even in an untrusted folder** (no trust dialog in `-p`). Security-relevant.
- Partial exception: `--bare` still loads skills from `.claude/skills/` (but skips `.claude/commands/` and `.claude/agents/`).
- Bare mode has access to **Bash, file read, and file edit** tools. Set `ANTHROPIC_API_KEY` (bare mode doesn't use subscription login). `--bare` is the **recommended mode for scripted/SDK calls and will become the `-p` default** in a future release.

### Output formats — when to use each
| Format | Flag | Use when |
|---|---|---|
| Text (default) | *(none)* | Human-readable prose; DON'T pipe to `jq`. |
| JSON | `--output-format json` | Scripts must parse output. Envelope with `result`, session ID, metadata, `total_cost_usd` + per-model cost breakdown. |
| Structured (schema) | `--output-format json` + `--json-schema` | Downstream code needs specific typed fields. Structured value lands in the **`structured_output`** field. |
| Stream JSON | `--output-format stream-json` (+ `--verbose` [+ `--include-partial-messages`]) | Real-time token streaming; newline-delimited JSON events, one per line. Last line is a `result` message. |

### Structured output with JSON Schema
```bash
claude -p "Extract the main function names from auth.py" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array",...}}}' \
  | jq '.structured_output'
```
- `--output-format json` wraps the response in an envelope but does **NOT** constrain content shape. Add `--json-schema` when you need a guaranteed shape for safe deserialization.
- Invalid schema → `claude` exits with `Error: --json-schema is not a valid JSON Schema` + validator diagnostic. (Pre-v2.1.205 it silently ignored invalid schemas.)
- `format` keyword (e.g. `"format": "email"`) is accepted but treated as an **annotation, not enforced**.

### GitHub Actions integration
Two ways to interact:
- **Interactive**: mention `@claude` in an issue/PR comment → Claude analyzes, implements, pushes commits.
- **Automation**: provide a `prompt` input → runs without a mention (e.g. on `push`, `pull_request`, `schedule`/`cron`). Results go to the **workflow run log** by default; Claude posts a comment only when the prompt directs it and it has a posting tool (e.g. code-review with `--comment`).

**Setup paths:**
- **Quick setup**: run `/install-github-app` from Claude Code (needs `gh auth login` + repo admin). Installs the GitHub App, adds the auth secret, opens a PR with the workflow file.
- **Manual setup**: install the app, add a secret, copy `examples/claude.yml` into `.github/workflows/`.

**Authentication secrets** (store as GitHub Secrets, never hardcode):
- `ANTHROPIC_API_KEY` → API key from Claude Console. Workflow input: `anthropic_api_key`.
- `CLAUDE_CODE_OAUTH_TOKEN` → OAuth token for a Claude subscription (Pro/Max/Team/Enterprise). Generate with `claude setup-token`. Workflow input: `claude_code_oauth_token`.
- For org-wide/shared secrets, prefer an **API key** (OAuth token is tied to one person's subscription).

**Passing CLI args to the action** — use the `claude_args` input:
```yaml
- uses: anthropics/claude-code-action@v1
  with:
    anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
    prompt: "Generate a summary of yesterday's commits and open issues"
    claude_args: |
      --max-turns 5
      --model claude-opus-4-8
      --allowedTools "mcp__github__list_commits,mcp__github__list_issues"
```

## Gotchas / exam traps

- **Hardcoding the API key** — never put `ANTHROPIC_API_KEY=sk-ant-...` in YAML/scripts. Store as a CI/GitHub secret, inject as env var.
- **Expecting session continuity** — each `-p` call is independent. A second `claude -p` in the same job has NO context from the first. Pass everything explicitly (prompt/stdin) or use `--continue`/`--resume`.
- **Parsing prose as JSON** — without `--output-format json`, Claude writes prose; piping to `jq` fails. Always pair `--output-format json` with any JSON parsing.
- **Omitting `--json-schema` for typed pipelines** — `--output-format json` wraps but doesn't constrain shape. Add `--json-schema` when downstream code expects specific fields.
- **Ignoring exit codes** — Claude exits non-zero on API errors, rate limits, schema-validation failures. Check the exit code or use `set -e`.
- **Sending unbounded diffs** — large diffs blow context/cost. Scope with `git diff -- '*.py'` or per-file steps. (stdin cap = 10MB.)
- **`@claude` trigger must be an exact word** — `/claude` or `@claude-bot` won't trigger. Confirm the GitHub App is installed, workflows enabled, secret set.
- **`GITHUB_TOKEN` breaks push-triggered workflows** — GitHub doesn't trigger workflows on commits made with the default `GITHUB_TOKEN`. Omit the `github_token` input so the action authenticates as the Claude GitHub App (whose pushes do trigger workflows), or pass a custom app token.
- **Who can trigger runs** (two checks; run fails if either rejects): **write access** — triggering user needs repo write (allow exceptions via `allowed_non_write_users` + custom `github_token`); **human actor** — bot actors rejected unless listed in `allowed_bots` (prevents Claude-triggering-Claude loops; also applies to `schedule` runs attributed to the last user who changed the `cron`).
- **`id-token: write` permission required** for the action's default GitHub App auth (and for OIDC identity federation).
- **`--allowedTools` needed even if a skill's frontmatter names the tool** — e.g. inline-comment MCP server posts only when `--allowedTools` in `claude_args` names it.
- **Fork PRs on public repos** — GitHub withholds secrets from fork-PR-triggered runs; reviews run only on same-repo branches.
- **Scheduled workflows** run only from the default branch; public repos disable the schedule after 60 days of no activity.

## Quick reference

**Headless CLI flags**
| Flag | Purpose |
|---|---|
| `-p` / `--print` | Non-interactive: run prompt once and exit |
| `--output-format json` | JSON envelope (`result`, session ID, metadata, `total_cost_usd`) |
| `--output-format stream-json` | Newline-delimited JSON events (needs `--verbose`; add `--include-partial-messages` for token deltas) |
| `--json-schema '<schema>'` | Constrain output shape → value in `structured_output` |
| `--max-turns <n>` | Cap agent turns |
| `--allowedTools "Bash,Read,Edit"` | Pre-approve tools (no permission prompt). Alias: `--allowed-tools`. Supports rule syntax e.g. `Bash(git diff *)` (space before `*` matters) |
| `--permission-mode <mode>` | Session-wide baseline: `auto`, `acceptEdits`, (default `-p` baseline is Manual) |
| `--bare` | Skip hooks/skills/plugins/MCP/memory/CLAUDE.md; fast, reproducible; recommended for scripts |
| `--continue` / `--resume <id>` | Continue most recent / specific session |
| `--model <id>` | Select model (e.g. `claude-opus-4-8`, `claude-sonnet-5`) |
| `--mcp-config <file-or-json>` | Load MCP servers |
| `--append-system-prompt` / `--system-prompt` | Add to / fully replace system prompt |
| `--debug` | Debug output |

**JSON envelope (`--output-format json`)**
```json
{ "role": "assistant", "content": "...", "stop_reason": "end_turn" }
```
Parse with `jq`: `SUMMARY=$(git diff HEAD~1 | claude -p "One-line summary" --output-format json | jq -r '.content')`

**Example JSON Schema** (code review)
```json
{
  "type": "object",
  "required": ["severity", "issues"],
  "properties": {
    "severity": { "type": "string", "enum": ["none","low","medium","high","critical"] },
    "issues": { "type": "array", "items": {
      "type": "object",
      "required": ["file","line","description"],
      "properties": {
        "file": {"type":"string"}, "line": {"type":"integer"}, "description": {"type":"string"}
      }
    }}
  }
}
```

**GitHub Action — minimal `@claude` workflow**
```yaml
name: Claude Code
on:
  issue_comment: { types: [created] }
  pull_request_review_comment: { types: [created] }
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write      # required for default GitHub App auth
      actions: read        # lets Claude read CI results on PRs
    steps:
      - uses: actions/checkout@v6
        with: { fetch-depth: 1 }
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

**Action inputs**: `prompt` (plain text or `/skill-name`; omit → responds to trigger phrase) · `claude_args` (CLI args) · `anthropic_api_key` / `claude_code_oauth_token` / `github_token` · `trigger_phrase` (default `@claude`) · `plugin_marketplaces` / `plugins` · `settings` (JSON or path) · `use_bedrock` / `use_vertex` / `use_foundry` (`"true"`).

**CI secret setup**: `export ANTHROPIC_API_KEY="sk-ant-..."` → set in CI secrets, injected as env var (`ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}`), never hardcoded.

**Cloud providers** (route inference through your account, auth via OIDC — no static creds): `use_bedrock: "true"` (Amazon Bedrock) · `use_vertex: "true"` (Google Cloud Agent Platform) · `use_foundry: "true"` (Microsoft Foundry).
