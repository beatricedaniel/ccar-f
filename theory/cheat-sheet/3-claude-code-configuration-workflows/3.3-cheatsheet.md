# Domain 3 · Task 3.3 — Apply Path-Specific Rules for Conditional Convention Loading

**Exam objective**: Scope `.claude/rules/` files to specific files via a `paths` glob in YAML frontmatter so conventions load *conditionally* — active only when Claude touches matching files — instead of globally.

---

## Key concepts

- **Default behavior**: Claude Code loads all files in `.claude/rules/` and applies them **globally** (unconditionally, to every file). This is the baseline that path-specific rules refine.
- **Path-specific (path-scoped) rule**: a rule Markdown file whose YAML frontmatter declares a `paths:` list of glob patterns. The rule is activated **only when the files currently being edited/read match** at least one pattern — otherwise it is **silently skipped**.
- **Conditional convention loading** = this whole mechanism: rules become active/inactive depending on **workspace context** (which files are in play).
- **Why it matters**: precision (conventions apply only where relevant), conflict avoidance (React rules can't bleed into DB migrations; API rules can't hit test helpers), maintainability (each rule owns one concern scoped to one area). Also reduces **noise and context/token cost**.
- **Rule file shape**: a `.md` file in `.claude/rules/`, optional YAML frontmatter (`description`, `paths`), then instruction prose. Files are discovered **recursively** (subdirs like `frontend/`, `backend/` are fine). One topic per file; descriptive filenames (`testing.md`, `api-design.md`).
- **When rules load**: into context **every session** (rules WITHOUT `paths`) OR **when a matching file is opened/read** (rules WITH `paths`). Trigger is Claude **reading a file matching the pattern — NOT on every tool use**.
- **Rules vs Skills**: rules load every session or on file match; **skills** load only when invoked or when Claude judges them relevant to the prompt — use skills for task-specific instructions that don't need to always be in context.

## Patterns & when to use them

| Situation | Use |
|---|---|
| Convention applies to whole project, all files | Rule with **no `paths`** (loads at launch, same priority as `.claude/CLAUDE.md`) |
| Convention applies only to one layer/area (components, API, tests) | Path-scoped rule with `paths:` glob |
| Task-specific instructions not needed in context all the time | **Skill**, not a rule |
| Must run at a fixed lifecycle point (before commit, after edit) regardless of Claude's choice | **Hook** (rules/CLAUDE.md are context, not enforcement) |
| Directory-specific conventions the natural way | Also possible via **nested `CLAUDE.md`** in a subdirectory (loads on demand when Claude reads files there) |

**Path-specific rule (`.claude/rules/`) vs nested `CLAUDE.md`**
- Both give directory/area-scoped conventions and both **load on demand**.
- **Path-scoped rule**: explicit glob control (`paths`), one concern per file, matches by extension/dir/combination, lives centrally in `.claude/rules/`. Preferred for precise convention scoping.
- **Nested `CLAUDE.md`** (in a subdirectory): loaded when Claude reads files in *that directory*; broader "everything under here" instructions.
- Root/parent `CLAUDE.md` + `CLAUDE.local.md` load at launch; **subdirectory** `CLAUDE.md`/`CLAUDE.local.md` load on demand when files there are read.

**Glob-scoped rules** — scope by extension, directory, or any combination; list multiple patterns; a file matching ANY pattern activates the rule. A file can activate **multiple rules** at once (e.g. `src/api/__tests__/users.test.ts` loads both the API rule and the testing rule).

## Gotchas / exam traps

- **Overly broad patterns**: `**/*.ts` for an API-only rule activates it everywhere TS is written. Tighten the prefix (`src/api/**/*.ts`).
- **Forgetting extension variants**: pattern `*.tsx` silently drops `.ts`, `.stories.tsx`, `.test.tsx`. List all extensions, use brace `{ts,tsx}`, or drop the extension filter (`src/components/**`) when the rule applies regardless of type.
- **Conflicting rules for same path**: two rules both matching `src/api/**/*.ts` with contradictory instructions → ambiguity; Claude may pick arbitrarily. Scope by concern; no two rules should make opposing claims about the same files.
- **Wrong root**: patterns match paths **relative to the project root**, NOT the `.claude/` directory. Write `src/components/**`, never `../../src/components/**`. (In `claudeMdExcludes` specifically, patterns match **absolute** paths.)
- **No match = silently skipped**: if no active file matches, the rule simply doesn't load (no error). Missing a rule entirely → Claude falls back to general behavior.
- **Not enforcement**: rules/CLAUDE.md are **context, not configuration**. No guarantee of strict compliance. For hard enforcement use hooks / managed settings (`permissions.deny`, etc.).
- **`--setting-sources` exclusion**: project rules are skipped if you exclude `project`. NOTE version quirk — **before v2.1.211**, on-demand rules (path-scoped + nested `.claude/rules/`) loaded **even when `project` was excluded**.
- **Symlink matching**: as of **v2.1.198**, path matching also works when Claude reaches a file through a symlinked path to the project dir. `.claude/rules/` supports symlinks (resolved/loaded normally; circular symlinks handled gracefully).
- **Compaction**: an instruction that disappears after compaction may be a path-scoped rule that hasn't matched a file since (or a nested CLAUDE.md not yet reloaded). Put must-persist instructions in CLAUDE.md.
- **Debugging**: use the `InstructionsLoaded` hook to log exactly which instruction files loaded, when, and why — useful for path-specific/lazy-loaded rules. Also `/context` → "Memory files".

## Quick reference

**Rule file with `paths` frontmatter**
```markdown
---
description: React component conventions for the component library
paths:
  - "src/components/**/*.tsx"
  - "src/components/**/*.stories.tsx"
---
# React Component Standards
- Export components as named exports, never default.
- Props interfaces prefixed with component name: `ButtonProps`, not `Props`.
```

**Glob pattern syntax**

| Pattern | Matches |
|---|---|
| `src/**/*.ts` | All `.ts` files anywhere under `src/` |
| `src/api/**/*.ts` | Only `.ts` under `src/api/` |
| `**/__tests__/**` | Any `__tests__` dir at any depth |
| `*.config.{js,ts}` | Config files in project **root** only |
| `src/components/**` | All files (any extension) under `src/components/` |
| `**/*.test.ts`, `**/*.spec.ts` | Test/spec files anywhere |
| `src/components/*.tsx` | React components in one specific dir (no recursion) |

- `**` = any number of path segments; `*` = within a single segment; `{a,b}` = alternatives (**brace expansion**).
- **Brace expansion multiplies**: `src/*.{ts,tsx}` → 2 patterns; `{a,b}/{c,d}/*.{ts,tsx}` → 8. Budget: whole `paths` list shares **1,000 expanded patterns / 4 MiB**; brace-free patterns don't count. Over-budget patterns are used unexpanded (literal braces match nothing). (Before v2.1.217, many brace groups could stall/crash the CLI.)
- `[` starts a bracket expression (`[abc]`). An unreadable `[` (e.g. `photos[2024/**`) is **invalid → matches nothing** (other patterns keep working). Escape a literal bracket: `photos\[2024/**`.

**How / when conditional rules load**
- Rule **without** `paths` → loaded unconditionally at launch, applies to all files, same priority as `.claude/CLAUDE.md`.
- Rule **with** `paths` → loads when Claude **reads a file matching the pattern**, not on every tool use.
- User-level rules (`~/.claude/rules/`) load **before** project rules → project rules get **higher priority**.

**Directory-scoped conventions layout**
```
your-project/
├── .claude/
│   ├── CLAUDE.md          # Main project instructions
│   └── rules/
│       ├── code-style.md  # global (no paths)
│       ├── api-design.md  # paths: src/api/**
│       └── testing.md     # paths: **/*.test.ts, **/__tests__/**
```

**Related (context, not core to 3.3)**: `@path/to/import` imports (loaded at launch, ≤4-hop depth, relative to importing file); `claudeMdExcludes` in settings to skip other teams' CLAUDE.md in monorepos (absolute-path globs, cannot exclude **managed policy** CLAUDE.md). CLAUDE.md size target **<200 lines**; Claude skips a CLAUDE.md file **over 4 MiB**.
