# Domain 3 · Task 3.1 — Configure CLAUDE.md Files with Appropriate Hierarchy and Scoping

**Exam objective**: Place `CLAUDE.md` instructions at the correct scope (managed / user / project / directory), know their load order and precedence, and use `@import` / `.claude/rules/` / path-scoping to keep instructions narrow — plus the parallel `settings.json` precedence stack.

---

## Key concepts

- **Two memory systems, both loaded at session start, both treated as context (NOT enforced config):**
  - **CLAUDE.md files** — instructions *you* write for persistent context.
  - **Auto memory** — notes *Claude* writes itself from your corrections/preferences (`~/.claude/projects/<project>/memory/`).
  - Enforcement note: CLAUDE.md is delivered as a **user message after the system prompt** — Claude tries to follow it, no strict-compliance guarantee. To *force* an action regardless of what Claude decides, use a **hook** (e.g. `PreToolUse`), not CLAUDE.md.
- **Merged into one instruction set** at the start of every session; broadest scope loads first, most specific last.
- **Directory-level files are ADDITIVE, not replacements** — a subdirectory `CLAUDE.md` extends parent instructions; all user + project rules stay active.
- **Conflict resolution: more specific (inner) level wins.** A `src/api/CLAUDE.md` "use async/await" overrides project-root "prefer callbacks."
- **Size target: under 200 lines per file.** Longer = more context consumed, worse adherence. Claude loads a CLAUDE.md up to **4 MiB**; skips a larger one.
- **Claude reads `CLAUDE.md`, not `AGENTS.md`** — bridge with `@AGENTS.md` import or a symlink `ln -s AGENTS.md CLAUDE.md` (Windows symlinks need Admin/Developer Mode → prefer the import).

## Patterns & when to use them

**Hierarchy — pick the narrowest correct scope ("Who needs to know this?"):**

| Level | Ask | Put it here |
|---|---|---|
| Managed / org | Every machine in the org | managed policy location (IT/DevOps) |
| **User** `~/.claude/CLAUDE.md` | Every project *I* ever touch | personal style, preferred languages, editor habits |
| **Project** `./CLAUDE.md` | Everyone on the team, every time | stack, conventions, team-agreed patterns |
| **Directory** `src/api/CLAUDE.md` | Only the engineer in this subsystem | domain-specific patterns that are noise elsewhere |
| **Local** `./CLAUDE.local.md` | Just me, just this project | sandbox URLs, personal test data (gitignore it) |

**When memory loads:**
- `CLAUDE.md` + `CLAUDE.local.md` in the CWD **and every directory above it** load **at launch**. Run in `foo/bar/` → loads `foo/bar/CLAUDE.md`, `foo/CLAUDE.md`, plus any `CLAUDE.local.md`.
- **Subdirectory** files (below CWD) load **on demand** — only when Claude reads a file in that directory.
- Within a directory, `CLAUDE.local.md` is appended **after** `CLAUDE.md` (personal notes read last at that level).
- Imported files load **at launch too** (splitting into imports helps organization, does NOT save context).
- `.claude/rules/*.md` **without** `paths` frontmatter load at launch (same priority as `.claude/CLAUDE.md`); rules **with** `paths` load on demand when matching files are opened.

**Imports — `@path/to/import` syntax:**
- Any CLAUDE.md can pull in another file: `@import .claude/rules/coding-style.md` or inline `@README`, `@package.json`.
- **Relative paths resolve to the file containing the import**, NOT the working directory. Absolute paths and `~/` allowed.
- **Max recursion depth: 4 hops** (docs); keep chains shallow (repo guidance: 2 levels — CLAUDE.md → rules, rules don't re-import).
- Import parsing **skips code spans / fenced blocks** — wrap a path in backticks (`` `@README` ``) to mention it literally without importing.
- **External import** (path resolves outside the working dir, e.g. `@~/.claude/...` in a *project* file) triggers a one-time **approval dialog**; declining disables it silently. User-scope files' imports are trusted without the dialog (except in Cowork/desktop sessions).

**`.claude/rules/` pattern:** break a big CLAUDE.md into focused topic files (`testing.md`, `api-design.md`), one topic each, discovered recursively (`frontend/`, `backend/`). Lets teams own files independently. Supports symlinks (circular symlinks handled). Use **skills** instead for task-specific instructions that shouldn't sit in context every session.

**Path-scoped rules (YAML `paths` frontmatter):** conditional rules that only apply when Claude works with matching files.
```yaml
---
paths:
  - "src/api/**/*.ts"
  - "tests/**/*.test.ts"
---
```
Glob patterns: `**/*.ts` (all TS anywhere), `src/**/*` (all under src), `*.md` (root markdown), brace expansion `src/*.{ts,tsx}`. Budget: 1,000 expanded patterns / 4 MiB per rule.

## Gotchas / exam traps

- **Everything in the project root** — a 600-line root CLAUDE.md loads for *every* file (DB rules distract Claude editing frontend). Fix: directory-level files + path-scoping.
- **User-level for project conventions** — `use React hooks` in `~/.claude/CLAUDE.md` follows you into backend-only repos. Project opinions → project level.
- **Directory file "replaces" parent** — WRONG, it's additive.
- **Contradictory instructions across levels** — inner wins, but it signals misconfiguration; document which level owns a decision, don't duplicate.
- **Deep/circular import chains** — hard to trace; cap depth.
- **Splitting into imports to save context** — it does NOT; imports load at launch like inline text.
- **CLAUDE.md as hard enforcement** — it's context, not config; use hooks / settings for enforcement.
- **Managed CLAUDE.md cannot be excluded** by user settings (org-wide always applies); regular files can be skipped via `claudeMdExcludes` (glob on absolute paths; arrays merge across layers — set in `settings.local.json` to stay machine-local).
- **`CLAUDE.local.md` is per-worktree** — only exists where created. Share across worktrees by importing from home: `- @~/.claude/my-project-instructions.md`.
- Block-level HTML comments `<!-- ... -->` are **stripped** before injection (free maintainer notes); comments inside code blocks are preserved.

## Quick reference

**CLAUDE.md locations (load order: broadest → most specific):**

| Scope | Location | Shared with |
|---|---|---|
| Managed policy | macOS `/Library/Application Support/ClaudeCode/CLAUDE.md`; Linux/WSL `/etc/claude-code/CLAUDE.md`; Windows `C:\Program Files\ClaudeCode\CLAUDE.md` | whole org |
| User | `~/.claude/CLAUDE.md` (+ `~/.claude/rules/`) | just you, every project |
| Project | `./CLAUDE.md` **or** `./.claude/CLAUDE.md` (+ `.claude/rules/`) | team (via version control) |
| Local | `./CLAUDE.local.md` | just you, this project (gitignore) |

- Managed content can also go inline as the **`claudeMd`** key inside `managed-settings.json` (honored in managed/policy settings only).
- `/init` generates a starter CLAUDE.md; `/context` → **Memory files** confirms what loaded; `--add-dir` doesn't load its CLAUDE.md unless `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`.

**Import syntax:** `@path/to/import` — relative-to-file, absolute, or `~/`; recurses ≤4 hops; skips code blocks.

**settings.json files & precedence (highest → lowest):**

| # | Level | File | Who |
|---|---|---|---|
| 1 | **Managed** | `managed-settings.json` / MDM / claude.ai console | org (nothing overrides) |
| 2 | **Command line** | `claude --settings '{...}'` / flags / env | you, this session |
| 3 | **Project local** | `.claude/settings.local.json` | you, this project (gitignored) |
| 4 | **Shared project** | `.claude/settings.json` | everyone in project |
| 5 | **User** | `~/.claude/settings.json` | you, every project |

- Higher level overrides same key below it. **Exception: list keys MERGE** (e.g. `permissions.allow`, `claudeMdExcludes` combine across scopes rather than replace).
- Key `settings.json` keys: `model`, `permissions.allow` / `ask` / `deny` (e.g. `"Bash(npm run test *)"`, `"Read(./.env)"`), `hooks`, `env`, `autoMemoryEnabled`, `autoMemoryDirectory`, `claudeMd` (managed only), `claudeMdExcludes`, `spinnerTipsEnabled`.
- Files are **strict JSON** — a `//` comment or trailing comma = Settings Error (Claude offers to fix at next start). Verify with `/status` → **Setting sources**.
- Some env vars override per-pair, not per-level: `ANTHROPIC_MODEL` beats the `model` key from any file.
- A few security keys honor the **stricter** value from a lower level over managed (e.g. `disableClaudeAiConnectors: true`, `enableArtifact: false`).

**Auto memory quick facts:** on by default; toggle `/memory` (writes `autoMemoryEnabled`) or `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Four note `type`s: `user`, `feedback`, `project`, `reference`. `MEMORY.md` index loads first **200 lines / 25KB** each session; topic files load on demand. Machine-local, one dir per git repo, not shared across machines/cloud.
