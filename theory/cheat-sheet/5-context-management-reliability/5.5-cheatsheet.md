# Domain 5 · Task 5.5 — Design Human Review Workflows and Confidence Calibration

**Exam objective**: Route only the *right* items to human reviewers by combining field-level confidence, stakes, and downstream impact — and calibrate confidence scores against measured accuracy rather than trusting the model's self-reported numbers.

---

## Key concepts

- **Uniform certainty is a myth.** A model can be 97% confident on a vendor name (structured header) and 58% on a handwritten date (footer) *in the same document*. Confidence varies by field, not just by document.
- **Goal of a review workflow**: "Not to review everything, but to review the *right things*." Reviewing everything doesn't scale; reviewing nothing lets errors propagate.
- **Field-level confidence > document-level confidence.** Aggregate (document) confidence hides variation. Surfacing per-field confidence lets you flag only uncertain fields instead of discarding/re-reviewing the whole document.
  - `ExtractedField` shape: `value`, `confidence` (0.0–1.0), `source` (`"structured" | "unstructured" | "inferred"`).
- **Confidence ≠ accuracy.** A confidence score is the model's *internal estimate*, not a guarantee. Must be measured against ground truth.
- **Overconfidence**: model reports 90% confidence but is only correct 70% of the time. Calibration = measuring the stated-confidence-vs-observed-accuracy relationship, then adjusting thresholds.
- **Calibration is per-document-type.** A model calibrated on invoices may be systematically overconfident on purchase orders. Never share one threshold across types.
- **Reviewer corrections are ground-truth data.** Feed them back into calibration measurements — this is the loop that keeps thresholds accurate.

---

## Patterns & when to use them

### Human-in-the-loop review triggers — involve a human when:
1. **Model confidence is low** — falls below a *calibrated* threshold.
2. **Stakes are high** — medical records, financial figures, legal documents (outsized consequences).
3. **Document type is novel** — limited training signal for a new category.
4. **Output feeds downstream automation** — a mistake will be silently compounded by later steps.

### Field-level flagging (`flagFieldsForReview`)
- Filter fields where `confidence < threshold`, return just those field names (e.g. `["invoiceDate", "taxId"]`).
- **Use when**: most of a document is trustworthy but a few fields are shaky. Route the fields, keep the document.

### Stratified sampling (`shouldSampleForReview`)
- Review a *representative subset* to measure system quality without reviewer burnout.
- Sample proportionally across **document types × confidence bands (high/medium/low) × edge cases**.
- **Higher sample rates** for low-confidence bands and novel types; **lower rates** for well-understood, high-confidence categories. Allocates reviewer capacity where it adds the most value.
- `SampleConfig`: `documentType`, `confidenceBand`, `sampleRate` (e.g. 0.05 = 5%).
- **Use when**: measuring/monitoring quality across a large volume — NOT the same as gating individual high-risk items (use trigger rules for that).

### Calibration (`CalibrationBucket` → `adjustThreshold`)
- Bucket predictions by confidence range; `accuracy = correctPredictions / totalPredictions`.
- If the 80–90% bucket only hits 65% actual accuracy → **raise the review threshold** for that document type (e.g. to 0.90) so more items get reviewed.
- Run calibration **per document type**, using a `targetAccuracy`.

### Review queue design
- **Priority-ordered, NOT FIFO.** Lowest confidence + highest downstream impact surface first.
- **Review priority score** = confidence × document-type risk weight × recency.
- **Surface flagged fields inline** (not the full document) to cut cognitive load and review fatigue.
- **Record corrections** and feed back into calibration.

### Supporting reliability mechanisms (from reference docs)
- **Strict tool use** (`strict: true` on custom tool definitions) → guarantees tool calls match your schema exactly. **Structured outputs** guarantee schema conformance (JSON outputs + strict tool use). Use these to reduce *validation-class* failures before they ever reach a reviewer.
- **Citations / Search results** → ground responses in source passages for verifiable, trustworthy output (helps reviewers verify fast).
- **tool_result error signaling** → tools return errors in the `tool_result` block so the coordinator can react (ties to D2 structured error responses).

## Gotchas / exam traps

- **Single threshold for all document types** ← WRONG. Over-reviews high-confidence types, under-reviews low-confidence ones. Calibration differs by type.
- **Conflating model confidence with accuracy** ← A 90% score is an estimate, not a guarantee. Always validate against ground truth.
- **Random sampling instead of stratified** ← Pure random under-represents rare document types and the edge cases that matter most.
- **Ignoring reviewer feedback** ← Corrections are ground-truth; not collecting/acting on them means calibration never improves.
- **Field-level confidence not surfaced to reviewers** ← If reviewers see only a pass/fail flag, they re-verify the *entire* document → wasted time + review fatigue.
- **"Review everything to be safe"** ← Not scalable; the objective is selective routing.
- **Document-level confidence to gate individual fields** ← hides field variation; flag at field level.

## Quick reference

### Human review triggers (memorize the 4)
| Trigger | Why |
|---|---|
| Low confidence (below calibrated threshold) | Model is uncertain |
| High stakes | Medical / financial / legal — outsized cost of error |
| Novel document type | Limited training signal |
| Feeds downstream automation | Error silently compounds |

### Confidence thresholds & calibration
- Confidence range: **0.0 – 1.0**. Example flag threshold: **0.8**.
- Overconfidence example: **90% stated → 70% actual**.
- Calibration fix: measured accuracy < target in a band → **raise the threshold** for that document type.
- `accuracy = correctPredictions / totalPredictions`. Calibrate **per document type**.

### High-stakes vs low-stakes routing
| | High-stakes / low-confidence / novel | Low-stakes / high-confidence / well-understood |
|---|---|---|
| Sample rate | Higher | Lower |
| Threshold | Stricter (more review) | Looser |
| Queue priority | Top (impact × low confidence) | Bottom |

### Calibration techniques
- Field-level confidence surfacing
- Confidence bucketing + reliability measurement (buckets → accuracy per band)
- Per-document-type threshold adjustment
- Reviewer-correction feedback loop
- (Foundational refs: Niculescu-Mizil & Caruana 2005; Guo et al. 2017 — temperature scaling, reliability diagrams)

### Approval gates / queue rules
- Priority-ordered, not FIFO
- Priority = confidence × risk weight × recency
- Surface flagged fields inline, not whole documents
- Log corrections → calibration
