# Domain 5 · Task 5.4 — Manage Context Effectively in Large Codebase Exploration

**Exam objective**: The context window is a finite working memory and the *first* bottleneck in large-codebase work — counter degradation with the Glob→Grep→Read funnel, externalized scratchpads, proactive `/compact`, and scoped subagent delegation.

## Key concepts

- **Context window = working memory.** Finite resource. In large-codebase exploration it's the bottleneck you hit first — *not* capability, *not* tool availability.
- **Context degradation** (the core failure): as you fill the window, two things happen —
  1. Raw token count climbs toward the limit → less room for new info.
  2. **Signal-to-noise ratio falls** → early, precise findings get buried under later file dumps; start-of-session instructions carry less weight when they're thousands of tokens behind the generation point. The model doesn't *forget*, but each item's influence on generation *drops*.
- **Symptoms of degradation**: repeating observations already made, dropping earlier constraints (e.g. stops honoring an acknowledged naming convention), reduced answer precision as the session grows.
- **Externalization** is the cure: write findings to a **scratchpad file** instead of trusting the transcript to hold them.
- **`/compact`**: summarizes the conversation and replaces verbose history with a condensed version, freeing context space. Anthropic also runs **auto-compaction** automatically when the session approaches the context limit.
- **Subagent delegation**: each subagent gets a **fresh context window** scoped to its slice; verbose work stays in the subagent, only a **summary** returns to the main conversation.
- **Incremental (funnel) exploration**: Glob → Grep → Read. Spend tokens only on files proven relevant.

## Patterns & when to use them

**Scratchpad file (externalized memory)** — use continuously.
- After every meaningful discovery, append a structured note: **file path + what was found + why it matters**.
- Survives `/compact` and session hand-off; gives Claude one dense source to re-read instead of re-reading dozens of source files.
- Example entry:
  ```
  ## rate-limit.middleware.ts
  - Sliding window, Redis store
  - Limit: process.env.RATE_LIMIT_MAX (default 100)
  - Applied globally in app.ts line 34
  - No per-route override present
  ```

**`/compact` at phase boundaries** — use *proactively*, before the window fills.
- Run after finishing a discrete investigation phase (e.g. after mapping the auth layer, before the data-access layer). NOT reactively after quality already dropped.
- **Always re-anchor after compaction**: re-read the scratchpad and restate the current objective explicitly. Treat re-anchoring as mandatory — the condensed summary may drop earlier constraints/goals.
- Custom preservation: `/compact Focus on code samples and API usage` tells Claude what to keep. Can also set compaction guidance in `CLAUDE.md`.

**Subagent / coordinator pattern** — use when the codebase has multiple *independent* subsystems.
- Delegate each slice to a subagent with **scoped instructions** (a directory, layer, or specific question). The value of delegation comes from the boundaries.
- Benefits: parallel exploration, no cross-contamination of context, each returns a focused summary (not a sprawling transcript).
- **Coordinator** defines boundaries, launches scoped subagents, collects summaries into the shared scratchpad — and **never reads raw files itself, only summaries.**
- Also delegate verbose one-off ops (running tests, fetching docs, processing logs) so the noise stays in the subagent.

**Incremental exploration funnel (progressive disclosure)** — the default for any "how does X work?" question.
1. **Glob** — pattern-match files to learn the codebase's shape (e.g. `**/*.middleware.ts` → 6 files: auth, cors, logging, rate-limit, timeout, validation).
2. **Grep** — search for the specific symbol/function (e.g. `"rateLimiter"` → hits in `rate-limit.middleware.ts` (def) + `app.ts` (registration)).
3. **Read** — open *only* the files grep flagged.
- Result: read 8 targeted files instead of 80 → far more capacity left for reasoning. "Start with Grep to earn the right to read a file."

## Gotchas / exam traps

1. **Reading every file "to be thorough"** — the #1 failure mode. Irrelevant files displace the context that holds the answer. Grep first.
2. **Treating the context window as the only memory** — findings living only in the transcript are one `/compact` away from being lost. Write to scratchpad *immediately* after a discovery.
3. **Running `/compact` reactively** — by the time you notice degradation, quality already dropped. Compact at natural phase boundaries.
4. **Launching subagents without scoped instructions** — an unscoped subagent behaves exactly like a full-context single agent; no benefit.
5. **Skipping re-anchoring after `/compact`** — the summary may omit specific constraints/objectives. Re-read scratchpad + restate goal every time. Mandatory, not optional.
6. **Confusing file count with coverage** — reading 50 files ≠ covering 50% of behavior. Behavior concentrates in a small fraction of files; invest tokens in high-signal files grep found, not a breadth-first sweep.
7. `/compact` in a fresh session prints `Not enough messages to compact.` — there's no history to summarize yet.
8. Compaction is itself a **large request** (it re-reads the whole conversation it summarizes). For a genuine fresh start with no continuity, `/clear` costs nothing.

## Quick reference

**`/compact` & auto-compaction**
- `/compact` — summarize + condense conversation history to free space. Use proactively at phase boundaries.
- `/compact <instructions>` — custom preservation (e.g. keep code samples / API usage).
- **Auto-compaction** — Claude Code auto-summarizes older history when the conversation nears the **auto-compact window** (context limit). A "context / auto-compact warning" is *not* a usage limit.
- `/clear` — fresh start, discards context, costs nothing (vs. `/compact` which is a large request). Use when switching to unrelated work. `/rename` before clearing so you can `/resume` later.
- `/context` — see what's currently consuming the window.
- `/usage` — check current token usage (or configure the status line to show it continuously).

**Offload exploration with subagents / Task tool**
- Spawn scoped subagents (Task tool) for independent subsystems and verbose ops (tests, docs, logs). Only the summary returns to main context.
- Set a cheaper model for simple subagent work (e.g. `model: haiku` in subagent config); reserve Opus for complex reasoning.
- Note: agent teams use ~7× the tokens of a standard session (each teammate = its own context window + Claude instance); keep team tasks small and self-contained.

**Grep/Glob over reading whole files**
- Funnel: **Glob** (shape) → **Grep** (locate symbol) → **Read** (only flagged files). Glob + Grep + Read = the canonical incremental exploration stack.
- Prefer CLI tools (`gh`, `aws`, `gcloud`) and code-intelligence plugins (go-to-definition) over broad reads; a single symbol lookup replaces a grep + several candidate reads.
- Hooks can preprocess data before Claude sees it (e.g. grep a 10k-line log for `ERROR`, return only matches) — tens of thousands of tokens down to hundreds.
- MCP tool defs are **deferred by default** — only names/instructions enter context until a tool is used; disable unused MCP servers (`/mcp`) to cut overhead.

**Context-window budgeting**
- Write **specific prompts** ("add input validation to the login function in `auth.ts`"), not vague ones ("improve this codebase") that trigger broad scanning.
- Use **plan mode** (Shift+Tab) for complex tasks so Claude scopes exploration before acting; course-correct early (`/rewind`, Esc) to avoid wasted context on wrong directions.
- Keep a scratchpad as durable memory; re-anchor from it after every `/compact`.
- Long idle sessions still burn tokens (background summarization, scheduled tasks, goal check-ins, cross-session messages, cache misses) — `/clear` unrelated work rather than leaving sessions open.
