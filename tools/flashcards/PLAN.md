# Plan: Anki-style flashcard CLI for CCAR-F prep

## Context

This repo is a study workspace for the **CCAR-F** exam. Theory content lives as PDFs under
`theory/<domain-folder>/`, one folder per domain (`1-agentic-architecture-orchestration` …
`5-context-management-reliability`), with **multiple PDFs per task** distinguished by a `D.T-`
filename prefix (e.g. `1.2-orchestrate-multi-agent-systems...pdf`, `1.2-multi-agent-systems.pdf`).

The user wants a **lean, single-file Python CLI** that turns a chosen domain+task's theory PDFs into
**10 Anki-style flashcards**, drills them until 100 %, and logs each session. Cards are generated by
calling the **Claude API** (per user choice) from the combined PDF text; PDFs are read with the
already-installed `pdftotext` (Poppler). The goal is a fast, friendly self-quiz loop that maps onto
how the exam is scored (D1–D5).

Key decisions already confirmed with the user:
- **Generation:** Claude API (structured JSON output).
- **Source:** *all* PDFs for the selected task (via `pdftotext`).
- **Runtime:** single-file Python 3, stdlib only (API call via `urllib`, no `pip install`).
- **Model:** default `claude-opus-4-8`, overridable via `FLASHCARDS_MODEL` (recommend
  `claude-haiku-4-5` for cheapest/fastest; this task is simple enough that Haiku is usually plenty).

## Deliverables

```
tools/flashcards/
  flashcards.py     # the CLI (single file, stdlib only)
  README.md         # one-screen usage + env vars
  decks/            # generated card sets, reused until reset:  decks/D1/1.1.json
  logs/             # per-session logs:  logs/D1/1.1/YYYYMMDD_HHMMSS.json
```
`decks/` and `logs/` are created on demand and are data, not code.

## How it works

### 1. Discover domains & tasks (no hardcoding)
- Domains: list the five `theory/<n>-*` folders, sorted by leading number → present as `D1..D5`
  with their kebab title humanised.
- Tasks in a domain: glob `theory/<domain-folder>/*.pdf`, extract the `D.T` prefix from each
  filename (regex `^(\d+)\.(\d+)-`), collect the distinct task numbers.
- Task label: for each task pick the PDF with the **longest slug** (the exam-objective doc) and turn
  its slug into a title (`-`→space, capitalised). Fallback to the bare `D.T` if none.

### 2. Menu flow (numbered `input()` prompts)
1. Show all domains → user picks one.
2. Show that domain's tasks → user picks one.
3. If `decks/D{d}/{d}.{t}.json` exists → ask: **[1] Study existing cards** / **[2] Reset (regenerate
   10 new cards)**. If it doesn't exist → generate automatically.

### 3. Generate a deck (Claude API)
- Collect `theory/<domain-folder>/{D.T}-*.pdf`, run `pdftotext -layout <pdf> -` on each (subprocess),
  concatenate the text (cap total chars, e.g. ~120k, to stay well within context).
- POST to `https://api.anthropic.com/v1/messages` via `urllib.request`:
  - headers `x-api-key: $ANTHROPIC_API_KEY`, `anthropic-version: 2023-06-01`, `content-type: application/json`
  - body: `model` (from `FLASHCARDS_MODEL` or `claude-opus-4-8`), `max_tokens: 8000`,
    `output_config: {format: {type: "json_schema", schema: {...cards...}}}` for guaranteed JSON,
    and a system/user prompt: *"You are creating exactly 10 Anki-style flashcards to test knowledge
    of CCAR-F Domain D, Task D.T. Use only the handout text below. Each card: a focused question
    (front) and a concise, self-contained answer (back). Cover the key concepts, patterns, and exam
    traps."* Include the extracted text.
  - Schema: `{type:object, additionalProperties:false, required:["cards"], properties:{cards:{type:array,
    items:{type:object, additionalProperties:false, required:["front","back"],
    properties:{front:{type:string}, back:{type:string}}}}}}`. (Structured outputs don't enforce array
    length, so the prompt asks for exactly 10; client validates count and retries once if not 10, else
    uses what came back.)
- Parse `content[0].text` as JSON, save to `decks/D{d}/{d}.{t}.json` with metadata (domain, task,
  model, generated_at, source_pdfs, cards).
- Auth: read `ANTHROPIC_API_KEY`; if missing, print a clear message pointing at `ant auth login` /
  exporting the key, and exit.

### 4. Study loop
- For each card: print the **front**, wait for Enter → print the **back** → prompt `[c]orrect /
  [w]rong / [q]uit`.
- After the full pass: compute % correct, print a report (correct/incorrect counts + %).
- If < 100 %: prompt **[1] redo all** / **[2] redo only missed** / **[q]uit**. "Only missed"
  re-drills just the wrong cards but the attempt's % is over that subset.
- Repeat, counting attempts, until 100 % (all cards correct in a pass) or the user quits.

### 5. Logging (written at session end)
Write `logs/D{d}/{d}.{t}/YYYYMMDD_HHMMSS.json` containing:
- `domain`, `task`, `started_at`, `model`, `deck_generated_at`
- `cards`: the full Q/A list studied
- `attempts`: array of `{attempt: n, scope: "all"|"missed", pct_correct, missed: [fronts...]}`
- `attempts_to_100`: integer (or `null` if the user quit before 100 %)
Timestamps use the real clock at runtime.

## Key implementation notes / reuse
- **PDF text:** shell out to `pdftotext` (already at `/opt/homebrew/bin/pdftotext`) — no Python PDF
  lib needed. Guard for a missing binary with a friendly error.
- **No third-party deps:** `urllib.request`, `json`, `subprocess`, `pathlib`, `os`, `re`, `datetime`,
  `glob` only. This honours the "very light tool, no build step" constraint. (If the user later wants
  retries/streaming, swapping in the `anthropic` SDK is a small change — noted in the README.)
- **Model override:** single constant `MODEL = os.environ.get("FLASHCARDS_MODEL", "claude-opus-4-8")`.
- Keep the file well under ~300 lines; small helper functions (`discover_domains`, `discover_tasks`,
  `extract_task_text`, `generate_cards`, `load_or_build_deck`, `study`, `write_log`, `main`).

## Verification (end-to-end)
1. `cd tools/flashcards && python3 flashcards.py` (with `ANTHROPIC_API_KEY` set, or
   `FLASHCARDS_MODEL=claude-haiku-4-5` for a cheap run).
2. Pick D1 → Task 1.1. Confirm it reads `1.1-*.pdf`, calls the API, and shows the domain/task menus.
3. Confirm `decks/D1/1.1.json` is written with 10 `{front,back}` cards.
4. Run one study pass: mark some wrong → verify the report %, the redo-missed path, and reaching
   100 % after correcting them.
5. Confirm `logs/D1/1.1/*.json` exists with `attempts`, per-attempt `missed`, `pct_correct`, and
   `attempts_to_100`.
6. Re-launch, pick 1.1 again → confirm the "study existing vs reset" prompt appears, and that reset
   regenerates a fresh deck.
7. Sanity: unset `ANTHROPIC_API_KEY` → confirm the clear auth error; rename `pdftotext` off PATH
   (or simulate) → confirm the friendly "pdftotext not found" error.
